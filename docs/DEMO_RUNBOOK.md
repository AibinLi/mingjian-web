# 10 分钟讲解与现场操作流程

> **Historical / legacy demo script:** 本文件保留阶段 10 的 Docker 演示稿，不再是当前 Windows 四服务 E2E 的操作手册。当前比赛启动和演示步骤请使用 [RUNBOOK.md](RUNBOOK.md)。

## 演示前检查（不计入讲解时间）

1. 现场电脑已安装 Docker Desktop/Engine 与 Docker Compose；准备已构建的本地镜像。不要在台上下载模型、数据或依赖。
2. 在项目根目录执行 `docker compose up -d`，等待 `docker compose ps` 中 API 和 gateway 为 `healthy`。
3. 用 `curl.exe -sS http://127.0.0.1:8000/health` 检查入口；浏览器打开 `http://127.0.0.1:8000`。
4. 准备一份团队拥有演示授权的小型 PNG 和一份团队拥有演示授权的小型无音频 MP4。不要携带 Celeb-DF 原始视频、用户媒体、抽取帧或未经许可样本。
5. 如现场默认 Compose 未挂载已核验权重，主动说明其会按设计显示 `unavailable`；不要临场下载或用分数冒充结论。

## 四个短案例的操作与预期

### 案例 A：受控图片的完整报告

- 操作：选择经授权的 PNG，点击“开始分析”，等待完成并打开报告。
- 观察点：作业状态、SHA-256、预处理工件、三轴卡片、质量信息、JSON 下载、删除按钮。
- 预期：默认 Compose 无模型挂载时，真实性为 `unavailable`、内容/来源为 Mock、综合建议为人工复核；这证明降级契约和报告路径，而非模型效果。

### 案例 B：离线 URL 引用

- 操作：输入公开 HTTPS 示例 URL 并提交，不上传文件。
- 观察点：报告保留受限 URL 引用；页面没有联网下载内容。
- 预期：不出现外部证据、真实检索或媒体结论。拒绝内网、回环、metadata、`.local` 和非默认端口 URL 时，说明这是输入边界。

### 案例 C：无音频视频的诚实降级

- 操作：上传经授权的无音频 MP4，打开报告。
- 观察点：音频和音画同步均标为 `not_applicable`；不是“低风险”。
- 预期：可展示关键帧和预处理信息；若视觉权重未挂载，真实性也为 `unavailable`。

### 案例 D：非法输入被拒绝

- 操作：选择 `.exe` 或 MIME/魔数不一致文件。
- 观察点：请求立即拒绝，不创建正常分析结论。
- 预期：解释扩展名、MIME 与魔数的共同校验；不要把被拒绝样本称为“检测出的攻击”。

## 离线降级方案

离线方案仍使用现场系统，不使用预录视频替代操作：

1. 若投影或浏览器故障，在终端运行 `docker compose ps` 与 `curl.exe -sS http://127.0.0.1:8000/health`，再通过 `curl.exe` 实际提交授权 PNG、读取 `/report` 和 DELETE 作业；展示返回的状态与审计字段。
2. 若模型未挂载，展示 `weight_available:false` 和 `unavailable`，并转到冻结评测工件解释为什么不将模型分数作为结论。
3. 若 Docker 无法启动，停止“现场系统已启动”的说法，展示 `README.md`、`docs/REHEARSAL_LOG.md` 和已保存的冻结 JSON 作为可复核材料；明确这不是现场系统替代演示，并记录故障。
4. 结束后执行 `docker compose down -v`，清除演示作业及命名卷。仅在确认不再需要现场数据时执行。
